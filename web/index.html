Give every QNX process only what it uses.

Tether records the abilities, channels and paths a QNX workload uses, writes a reviewable policy, and checks the workload again on a secure boot.

Observe. Tighten. Enforce. Verify.

Built on the QNX security-policy tools that ship with SDP 8.0, so the policy QNX enforces is the one you can read.

Observe

The app runs its normal workload under secpolgenerate.

Tighten

Tether keeps one type's rules, drops what went unused and ranks each grant by risk.

Enforce

secpolcompile checks it, then QNX reboots with it enforced (--secpol=secure).

Verify

Compare the two workload results and inspect the recorded denials alongside the policy.

Why it matters

  • Hand-written QNX policies are slow to write and drift from the code.
  • Running as root hands an exploited bug the whole machine.
  • Tether turns one recorded run into a reviewable, diffable policy file.

Try it on your machine

git clone https://github.com/himanshu748/tether-qnx
cd tether-qnx
python -m tether.cli tighten examples/offline/observed.secpol \
  --type sensor_t --unused examples/offline/unused.secpol \
  --json tether-offline.json
